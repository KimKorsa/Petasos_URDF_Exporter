# Petasos 익스포트 신뢰성 강화 설계

## 목적과 범위

사용자가 승인한 세 가지 개선: 충돌 원인 진단, 익스포트 일치 검증,
수동 모듈 기반 MoveIt 그룹 생성. 기존 UI 디자인과 버튼 크기는 유지한다.
현재 폴더의 미커밋 변경과 사용자가 지정한 모듈 범위를 보존한다.
ROS 2 Humble의 현재 실행 경로를 유지하며 Gazebo 버전 이전은 포함하지 않는다.

## 접근 방식

기존 exporter의 analysis 출력과 MoveIt 생성·검사 흐름을 확장한다.
검사 로직은 별도 작은 모듈로 분리하고 exporter는 입력과 결과를 연결한다.
새 대형 UI를 만들거나 충돌을 숨기는 자동 제외 기능을 도입하지 않는다.
단순 경고만 추가하는 대안은 실제 오류를 구분하지 못하므로 선택하지 않는다.
전체 시뮬레이터 이전은 기존 환경을 바꾸므로 별도 과제로 남긴다.

## 1. 충돌 원인 진단

- 정적 검사: 생성된 collision mesh의 존재, 유한 좌표, 빈 형상,
  폐곡면 여부, 면 수와 로컬 bounds를 기록한다.
- 생성 URDF의 순기구학으로 영점 자세에서 collision bounds를 월드로 변환한다.
  AABB 중첩은 실제 충돌이 아니라 `suspected_overlap`으로만 표시한다.
- 가능한 정밀 검사 백엔드를 사용할 수 없으면 정밀 판정은 `unverified`다.
  의존성 미설치를 충돌 없음으로 처리하지 않는다.
- ROS/MoveIt 진단은 state validity 서비스의 contact 정보를 사용한다.
  링크 쌍, 검사한 관절 값, contact 정보, 사용한 충돌 제외 설정을 함께 기록한다.
  서비스 unavailable/timeout은 `unverified`로 기록한다.
- 인접 링크와 ACM 제외 대상은 검사 결과에 표시하되 자동으로 제외를 추가하지 않는다.
- 보고서는 `analysis/collision_diagnostics.json`에 저장한다.
  bounds 의심과 MoveIt 실제 판정은 별도 항목으로 유지한다.

## 2. 익스포트 일치 검증

- exporter가 조인트·물성을 정규화한 뒤의 기준값을 사용한다.
  CAD 원시값, 사용자의 편집값, 내보내기 정규화 값을 혼동하지 않는다.
- 최종 생성 URDF/xacro를 펼친 결과와 기준값을 비교한다.
  조인트 parent/child, 원점 xyz, 회전 행렬, 축, 타입, 제한,
  mimic driver/multiplier/offset, 질량, COM, 관성 행렬이 대상이다.
- 회전은 Euler 문자열 대신 행렬로 비교하며 축의 물리적 방향과
  영점 순기구학을 함께 검사한다. 파일 존재만으로 일치 판정하지 않는다.
- XYZ/COM은 미터, 각도는 라디안이다. 비교는 절대 오차 1e-8,
  상대 오차 1e-6을 기본으로 하고 보고서에 사용한 허용 오차를 남긴다.
- 독립 조인트의 시작 값은 0이다. mimic 종속 값은 식에 따라 계산한다.
  0이 제한 밖이면 중간값으로 조용히 대체하지 말고 오류를 보고한다.
- ROS 실행 시 관측 joint_states와 시작 값·mimic 연동을 별도 검사한다.
  정적 일치와 실동작 검증 상태는 분리한다.
- 보고서는 `analysis/export_consistency.json`에 저장한다.
  오류는 한국어 요약과 식별 가능한 링크/조인트 이름을 포함한다.
  새 구조 검증 실패는 익스포트 성공으로 반환하지 않으며 기존 출력 보존 흐름을 따른다.

## 3. 모듈별 MoveIt 그룹

- 수동 지정 모듈의 안정 ID를 export_name_map으로 실제 URDF 이름에 매핑한다.
  모듈 경계, 이름, 컨트롤러 소유권을 임의 변경하지 않는다.
- 모듈 안의 가동 조인트를 그룹에 포함하고, 직접 제어 목록에서는 mimic
  종속 조인트를 제외한다. 모듈의 외부 부착 조인트는 모듈 내부 구동축으로 추정하지 않는다.
- 그리퍼는 기존 GripperActionController 지정으로 역할을 판단한다.
  이름에 gripper가 들어간다는 이유만으로 역할을 추정하지 않는다.
- 단일 직렬 팔 체인은 KDL 설정을 사용한다. 분기형/병렬형 그룹과 그리퍼에
  검증되지 않은 KDL을 일괄 적용하지 않는다. 지원하지 않는 구조는 이유를 보고한다.
- 모듈이 없는 기존 프로젝트는 기존 arm 그룹과 home 이름을 유지한다.
  모듈 적용 시 팔의 비모듈 구동축을 arm으로 유지하고 모듈별 그룹을 추가한다.
- SRDF 그룹, 영점 named state, controller mapping, 검사 대상 그룹을 함께 생성한다.
  안전한 이름 정규화 후 충돌하는 그룹 이름은 덮어쓰지 않고 오류로 처리한다.
- 기존 Assistant 작성 설정은 재생성 시 덮어쓰지 않는다.
  Petasos 생성 설정 변경은 별도 staging 결과와 차이 보고서로 제공한다.

## 검사와 실패 처리

세 기능은 순서대로 구현하며 각각 테스트를 갖춘다. 충돌 판정이 unavailable인
환경에서도 정적 검사와 익스포트는 가능하지만 실동작 성공을 주장하지 않는다.
UI에는 기존 결과/오류 표시 경로를 활용하고 전체 레이아웃을 변경하지 않는다.

필수 회귀 케이스: AABB만 겹치는 비충돌 형상, 실제 충돌 contact,
ROS/정밀 검사 unavailable, 회전 표현만 다른 동일 자세, 잘못된 COM/축,
0 제한 위반, mimic 체인/offset, 팔+그리퍼 모듈, 그룹 이름 충돌,
분기 그룹, 모듈 없는 기존 프로젝트, Assistant 사용자 설정 보존.

## 인수 기준

보고서가 실제 판정·의심·미검증을 구분하고, 내보낸 값의 차이를 항목별로
찾아낼 수 있어야 한다. 팔과 그리퍼 설정이 분리되며 mimic 종속 축에 직접
제어 명령을 보내지 않아야 한다. 기존 UI와 저장 프로젝트가 호환되어야 한다.
완료 보고에는 자동 테스트 결과와 실제 ROS/MoveIt 실행 여부를 별도로 명시한다.
