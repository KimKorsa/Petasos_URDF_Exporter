# 수동 선택 기반 재사용 로봇 모듈 설계

작성일: 2026-09-28
대상: Petasos_A_4 / Petasos_URDF_Exporter
상태: 사용자 검토용 설계안. 제품 코드 구현과 GitHub 업로드는 아직 하지 않는다.

## 1. 목적과 사용자 합의

본체의 편집 결과를 유지하면서 그리퍼를 별도로 저장·재사용·교체할 수 있게 한다.
단순히 출력 파일만 나누는 것이 아니라, 다른 Petasos 프로젝트에도 가져올 수 있는 모듈을 만든다.

사용자가 확정한 요구사항:

- 로봇 구조 트리에서 모듈에 포함할 링크와 조인트를 수동으로 선택한다.
- Ctrl+클릭 다중 선택과 드래그 영역 선택을 지원한다.
- 선택 링크의 하위 구조 전체를 자동으로 포함하지 않는다.
- 모듈은 링크 병합, 컨트롤러 그룹과 별개의 개념이다.
- 모듈별 Xacro를 생성하고 실행 시에는 하나의 로봇 설명으로 결합한다.
- 추후 이동 모듈에도 확장할 수 있는 데이터 구조를 사용한다.

성공 기준은 수동으로 지정한 그리퍼를 저장하고 다른 로봇에 붙이거나 교체한 뒤,
이름·좌표·메시·물성·조인트 참조가 깨지지 않는 것이다.

## 2. 현재 코드와 변경 경계

- `URDF_Exporter/core/web_ui.py`: 트리 렌더링, 링크 그룹 선택, 컨트롤러 선택, 속성 편집,
  저장/실행 취소가 있는 위치다. 모듈 선택 모드를 추가하되 기존 선택 모드와 혼동하지 않는다.
- `URDF_Exporter/standalone/server.py`: `ProjectStore`가 프로젝트 상태와 이름별 작업을 저장한다.
  모듈 라이브러리 API를 연결하되, 아카이브 처리와 그래프 검증은 별도 모듈로 분리한다.
- `URDF_Exporter/standalone/exporter.py`: 링크별 메시 합치기, 물성, 컨트롤러, MoveIt 생성 경로다.
  링크 이름 표준화 전후의 ID 매핑을 보존하고 출력 분할을 연결한다.
- `URDF_Exporter/core/Write.py`: 현재 전체 링크와 조인트를 최상위 Xacro에 쓴다.
  공통 링크/조인트 직렬화를 재사용하여 모듈별로 출력 대상을 나눈다.
- `moveit/`: URDF와 YAML 이름·인터페이스가 일치하도록 모듈 인스턴스를 해석한 결과를 사용한다.

전용 책임은 모듈 도메인 검증, 모듈 파일 입출력, 모듈 출력으로 분리한다.
이번 기능과 관계없는 UI 전체 리팩터링이나 로봇 제어 기능 변경은 하지 않는다.

## 3. 접근 방식과 범위

선택한 방식은 Petasos 재사용 모듈 아카이브와 Xacro 모듈 출력을 함께 제공하는 것이다.
출력 파일만 분리하는 방식은 편집기에서 교체할 수 없고, 모듈마다 ROS 패키지까지 나누는
방식은 첫 버전의 의존성·설치 경로 관리 비용이 크므로 채택하지 않는다.

이번 설계에서 제안하는 1차 범위:

- 그리퍼처럼 본체와 한 곳에서 연결되는 끝단 모듈을 생성·저장·장착·교체한다.
- 사용자가 선택한 항목들이 연결된 하나의 그래프인지 검사한다.
- 모듈에서 미선택 자식 구조로 이어지는 연결은 첫 버전에서 허용하지 않는다.
  누락된 항목을 자동 포함하지 않고 외부 연결 목록을 표시한다.
- `world`, `base_footprint`, 로봇 본체 루트, 중첩 모듈, 같은 링크의 중복 모듈 소속은 제외한다.
- 이동 베이스처럼 상부 로봇을 지지하는 모듈은 후속 확장 대상이다.
  현재부터 일반적인 module/attachment 명칭을 사용하되, 다중 장착 포트 구현은 하지 않는다.

이 제약은 자동 하위 선택을 뜻하지 않는다. 선택은 끝까지 수동이며, 잘못된 선택은
원래 상태를 보존한 채 진단한다. 1차 연결 범위 제약은 이 문서의 사용자 검토 대상이다.

## 4. 사용자 흐름

### 4.1 지정과 편집

1. 트리 도구 모음의 `모듈 지정`으로 전용 선택 모드에 들어간다.
2. Ctrl+클릭으로 링크 카드와 조인트 라벨을 추가/제외한다.
3. 빈 공간 드래그는 카드 또는 조인트 라벨의 중심이 사각형 안에 있는 항목을 선택한다.
   Ctrl+드래그는 기존 선택에 추가한다. 배선 전체가 가로질렀다는 이유로 조인트를 선택하지 않는다.
4. 선택 목록에 링크 수, 내부 조인트 수, 본체와의 연결 조인트를 구분해서 표시한다.
5. `모듈 생성` 시 서버가 범위와 참조를 검사한다. 통과한 경우 이름과 표시 색상을 설정한다.

링크 내부의 CAD 부품은 링크와 함께 보존한다. 링크를 분해하거나 한 링크의 일부 부품만
모듈에 넣으려면 기존 링크 분리 기능을 먼저 사용한다.

범위 내부의 연결 조인트도 수동 선택 대상이다. 내부 조인트가 빠지거나 선택 조인트의
끝점 링크가 빠진 경우 항목 이름을 표시하고 생성을 막는다. 본체와의 연결 조인트는
모듈 내부 조인트와 구분되는 장착 연결이며, 포함 목록에 읽기 쉽게 별도로 표시한다.

ESC는 선택 작업만 취소한다. 생성된 모듈은 삭제하지 않는다.
다른 그룹화/컨트롤러 선택 모드와 동시에 활성화하지 않는다.

### 4.2 트리 표시와 속성

- 모듈은 색상 배지와 옅은 외곽 영역으로 표시한다. 컨트롤러 라벨과 별도의 라벨 위치를 사용한다.
- 라벨을 누르면 선택 항목 속성에 모듈 이름, 포함 목록, 장착 링크, 장착 XYZ/RPY를 표시한다.
- XYZ UI 단위는 mm, RPY UI 단위는 degree, 내부 및 URDF 단위는 m/rad다.
- `범위 수정`, `라이브러리에 저장`, `교체`, `모듈 지정 해제`를 제공한다.
- 지정 해제는 메타데이터만 없애며 링크·조인트·메시·현재 자세는 보존한다.
- 범위 수정은 기존 모듈 선택을 초기값으로 열고, 적용 전까지 기존 모듈은 유지한다.

### 4.3 저장·장착·교체

- 저장된 모듈은 프로젝트에 종속되지 않는 로컬 라이브러리에 나타난다.
- `.petasos-module.zip`로 내보내거나 가져올 수 있다.
- 장착 시 부모 링크, 이름 접두사, XYZ/RPY를 선택한다. 새 장착 조인트의 기본값은 fixed다.
- 기존 조립품에서 모듈을 지정하는 동작은 원래의 장착 조인트와 조립 자세를 바꾸지 않는다.
- 교체는 기존 모듈을 선택한 상태에서 수행하고, 이전/새 포함 목록과 이름 변경을 미리 보여준다.
- 교체 시 본체 링크, 본체 조인트, 기존 장착 연결의 부모·타입·설정·변환을 유지한다.
  장착 조인트의 child만 새 모듈 루트로 연결한다.
- 새 모듈의 루트 장착 프레임을 기존 장착 프레임에 맞춘다. 서로 다른 그리퍼의 TCP가
  같은 위치라는 보장은 하지 않으며, TCP 자동 일치/IK 자동 보정은 이번 범위에서 제외한다.
- 장착/교체가 실패하면 원래 프로젝트가 그대로 남아야 한다. 각각 한 번의 실행 취소로 복원한다.

## 5. 데이터와 식별자

기존 트리 구조를 유지하고 루트에 버전이 있는 `_modules` 메타데이터를 추가한다.
이름 변경과 자동 링크 번호 재정렬 때문에 모듈 소속이 바뀌지 않도록 링크·조인트에
영속적인 내부 ID를 부여한다. 기존 프로젝트는 로드 시 누락 ID만 보충하고 저장 때 유지한다.
중복 ID는 오류로 처리하며, 모듈 가져오기에서는 새 인스턴스 ID를 발급한다.

모듈 인스턴스가 저장하는 정보:

- 스키마 버전, 인스턴스 ID, 표시 이름, 색상, 소스 라이브러리 모듈 ID
- 포함 링크 ID 목록, 내부 조인트 ID 목록, 루트 링크 ID
- 외부 부모 링크 ID, 장착 조인트 ID, 인스턴스 접두사

장착 변환의 실제 값은 기존 장착 조인트에 한 번만 저장한다.
모듈 속성에서 XYZ/RPY를 수정하면 이 조인트를 갱신한다. 이중 변환 필드를 만들지 않는다.

라이브러리 모듈의 조립 기준은 루트 링크 프레임이다. 원본 CAD 절대 좌표로 저장된
부품 배치와 스냅 데이터는 이 기준으로 변환한다. 이미 링크 기준인 visual/collision 원점,
무게중심·관성 및 부모 링크 기준인 조인트 원점·축은 해당 로컬 프레임 의미를 유지한다.
장착할 때 조립 변환을 한 번만 적용하며, 메시나 관성에 같은 변환을 중복 적용하지 않는다.
라이브러리는 저장 당시의 스냅샷이며, 이미 장착된 인스턴스가 자동 갱신되지는 않는다.

아카이브에는 manifest, 링크·조인트·부품 데이터, 사용 재질, 컨트롤러 정의, 필요한 메시만 넣는다.
버전 1만 읽으며 알 수 없는 버전은 오류와 함께 거부한다. 로컬 파일 절대 경로는 포함하지 않는다.

## 6. 그래프·참조 검증

생성, 범위 변경, 라이브러리 저장, 장착, 교체, 익스포트 전에 같은 서버 검증기를 사용한다.

- 선택 범위가 비어 있지 않고 모든 ID가 실제 존재해야 한다.
- 선택 링크 사이에 필요한 조인트가 선택돼야 하며, 내부 그래프가 연결된 트리여야 한다.
- 외부에서 들어오는 장착 연결은 정확히 하나여야 한다.
- 외부로 나가는 연결, 다른 모듈과 중복 소속, 순환 연결은 차단한다.
- 외부 조인트를 참조하는 mimic 및 외부에서 모듈 내부를 참조하는 mimic은 차단한다.
- 모듈 내부와 외부 조인트가 섞인 컨트롤러 그룹은 자동 분할하지 않는다.
  사용자에게 해당 컨트롤러의 분리가 필요하다고 표시한다.
- 모듈 이름·접두사는 안전한 ROS 이름으로 검사하고, 중복 이름은 고유 접미사를 제안한다.
- 가져올 때 링크, 조인트, 부품, 재질, 컨트롤러와 mimic 참조를 같은 매핑으로 다시 지정한다.
- 원본 프로젝트에 없는 메시·물성 데이터는 누락 오류로 처리한다.

삭제·링크 병합·배선 변경이 기존 모듈 경계를 깨뜨리는 경우 조용히 메타데이터를 잃지 않는다.
변경 전 영향을 표시하고 모듈 지정 해제 또는 범위 수정을 요구한다.
CAD 재가져오기는 기존 매칭으로 ID를 보존하고, 완료 전 모듈 검증을 수행한다.
검증 실패 시 기존 프로젝트에 적용하지 않는다.

## 7. 출력과 제어 구성

모듈 없는 프로젝트의 출력 형식과 동작은 그대로 유지한다.
모듈이 있으면 동일한 description 패키지 안에서 다음 책임으로 나눈다.

- 최상위 robot Xacro: 본체 정의, 모듈 include/호출, 본체와 모듈의 장착 조인트
- `urdf/modules/<module_id>.xacro`: 모듈 내부 링크·조인트 매크로
- 모듈 소유 메시: 해당 패키지의 메시 하위 경로에 복사
- 제어 정의: 모듈 조인트의 ros2_control 내용을 매크로로 분리하고 기존 ros2_control 블록 안에서 호출
- 전체 YAML/SRDF: 펼쳐진 최종 로봇의 이름·관계로 일관되게 생성

모듈 때문에 한 링크의 메시를 더 거칠게 만들거나 여러 링크를 한 STL로 합치지 않는다.
기존 링크 단위 visual/collision 생성 정책을 유지한다.

실행에 전달하는 것은 결합된 단일 로봇 설명이다. 같은 링크나 조인트를 본체와 모듈 양쪽에
중복 출력하지 않는다. 모듈 출력 때문에 중복 ros2_control 시스템이나 컨트롤러 spawner를 만들지 않는다.

컨트롤러 YAML은 해당 조인트들이 실제 제공하는 인터페이스만 사용한다.
모듈 교체 후에는 MoveIt 설정도 새 로봇 구조로 다시 생성해야 하며, 기존 Assistant 수동 수정이
자동 보존된다고 안내하지 않는다. 지원되지 않는 그리퍼 제어 타입이나 외부 SRDF 참조는
명시적인 오류로 보고하며 임의의 arm_controller로 대체하지 않는다.
실행 중인 ROS/MoveIt에 대한 핫스왑은 지원하지 않는다. 종료·재익스포트·재실행 절차를 안내한다.

## 8. 파일 안전성과 호환성

- 라이브러리 디렉터리와 업로드 아카이브는 프로젝트 소스 및 Git 추적 대상에서 제외한다.
- ZIP의 절대 경로, `..`, 심볼릭 링크, 중복 엔트리, 허용되지 않은 파일 유형을 거부한다.
- 압축 파일 200 MiB, 압축 해제 총량 1 GiB, 파일 수 10,000개를 초기 상한으로 적용한다.
- 임시 디렉터리에서 전량 검증 후 원자적으로 라이브러리에 등록한다.
- 교체 전에 필요한 새 파일을 먼저 검증하고, 검증 후 프로젝트 상태를 한 번에 교체한다.
  실행 취소가 참조하는 기존 메시를 즉시 삭제하지 않는다.
- 모듈 필드 없는 기존 작업은 정상 로드·편집·익스포트돼야 한다.
- 저장/복원과 실행 취소/다시 실행에서도 ID와 모듈 소속을 보존한다.
- 원본 CAD, 사용자 저장 작업, 기존 라이브러리 항목을 가져오기 동작으로 덮어쓰지 않는다.

## 9. 검증 기준

자동 테스트:

1. 선택 범위 그대로 생성: 미선택 하위 링크가 자동으로 포함되지 않는다.
2. 연결 누락·외부 경계·mimic·혼합 컨트롤러 참조를 정확한 항목 이름과 함께 진단한다.
3. 이름 변경과 자동 번호 정렬 후에도 모듈 소속이 유지된다.
4. 라이브러리 저장/다른 프로젝트 장착 후 메시·질량·관성·상대 자세가 보존된다.
5. 같은 모듈 두 번 장착 시 이름과 ID가 충돌하지 않는다.
6. 교체 실패는 원래 상태를 보존하고, 성공 후 실행 취소는 이전 모듈을 복원한다.
7. Xacro 펼치기 전후의 링크·조인트 수, FK, 관성, 재질, mimic이 일치한다.
8. YAML/SRDF에 삭제된 모듈 조인트 이름이 남지 않고 없는 인터페이스를 요청하지 않는다.
9. 아카이브 경로 이탈·누락·크기 초과를 거부한다.
10. 모듈 없는 기존 회귀 테스트가 통과한다.

UI 확인은 Ctrl+클릭/영역 선택, 확대·축소 후 선택 위치, 모듈과 컨트롤러 라벨 구별,
속성 편집, 저장/재로드, 교체 및 실행 취소를 포함한다.
WSL 실행 검증은 Xacro 확장, RViz 시각 확인, 지원되는 MoveIt 구성에서 컨트롤러 활성화와
Plan/Execute를 구분해서 기록한다. 실제 실행을 하지 못하면 코드 테스트만으로 성공을 선언하지 않는다.
